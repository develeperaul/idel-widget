## Формат передачи Vue → Unreal

`src/bridge.js` формирует сообщение:

```json
{"id":"idel_2","method":"scene.setWeather","params":{"weather":"rain"}}
```

- `method` — имя команды, по которому Unreal выбирает действие.
- `params` — параметры команды; для кнопок без параметров передаётся `{}`.
- `id` — счётчик внутри одного экземпляра страницы. Между Web Browser и после
  перезагрузки значения могут повторяться: это не глобальный идентификатор.
- В консоль отправляется `IDEL:` + JSON сообщения.
- В браузере одновременно отправляется `window`-событие `idel-command`;
  `event.detail` содержит то же сообщение. Это второй канал того же действия.
- Строки `IDEL:DEBUG ...` — диагностические сообщения, не JSON-команды.

Таблицы ниже указывают имена `method`. Локальные Vue-события отдельно перечислены
в конце файла: они не отправляются в Unreal автоматически.

## 1. Загрузка и вход в сессию — экраны 01–03

| Источник | Команда | Параметры | Что реализовано |
| --- | --- | --- | --- |
| Загрузка любого экземпляра виджета | `ui.ready` | `{version: 1, panel}` | Отправляется после установки публичного JS API. `panel`: `full`, `session`, `environment`, `toolbar`, `compass`, `saved`, `gallery`. |
| «Войти», существующий клиент | `session.started` | `{mode:"manager", mock:false, manager:{id,name}, client:{id}}` | `POST /api/session` находит клиента по телефону, создаёт сессию с его сохранённым менеджером. |
| «Войти», новый клиент | нет до завершения регистрации | — | Первый запрос открывает второй шаг. `GET /api/managers` загружает список. `POST /api/session/register` сохраняет ФИО и менеджера в клиенте, затем отправляется `session.started` с параметрами выше. |
| «Гостевой вход» | `session.started` | `{mode:"guest", mock:false, manager:null, client:null}` | Создаётся серверная гостевая сессия. |
| Явное превью `IdelConfig.realSession:false` | `session.started` | `{mode, mock:true, manager, client}` | Те же шаги с локальными данными; ID имеют префикс `mock-`, серверного токена нет. |
| «Сохранить избранное и выйти» / «Выйти без сохранения» / `IdelSession.reset()` | `session.ended` | `{savedLocally:boolean,archiveId:string|null}` | При успешном выходе очищает состояние Vue. `archiveId` — только ID архива избранного в IndexedDB этого устройства. Если запись не удалась, выхода и события нет. Unreal должен удалить PNG завершённой сессии. |

Неверный телефон, неполные данные регистрации или ошибка API не отправляют
`session.started`. Телефон, ФИО клиента и Bearer token не входят в события или
публичное состояние `IdelSession`; клиент передаётся только как `{id}`.
В текущем `index.html` включён реальный API по HTTP с явным `allowHttpSession:true`.
«Назад», очистка поля, выбор менеджера, клавиатура и галочка согласия работают
локально и не отправляют отдельные команды Unreal. В `panel=session` Vue скрывает своё содержимое;
сворачивание самого Web Browser выполняется отдельно в Unreal.

Дополнительно при входе отправляется браузерное `window`-событие `idel-session`:
его `detail` содержит объект сессии без оболочки `{id, method, params}`.
Это уведомление о том же входе, а не ещё одна сессия.

| Кнопка | ID категории / значение `data-category` |
| --- | --- |

| Кафе | `cafe` |

| Магазины | `shop` |

Например, если включены только школы и кафе:

```json
{"id":"idel_12","method":"scene.setInfrastructure","params":{"categories":["school","cafe"]}}
```

Команда передаёт **весь актуальный набор**, а не только нажатую категорию.
Пустой массив означает «выключены все категории». Порядок ID не должен влиять
на результат. Изначально и после сброса сессии включены все девять категорий.

Vue меняет состояние кнопок и отправляет команду. **Точки, координаты и привязка
к объектам принадлежат Unreal**. Unreal должен сопоставить ID с группами точек
и изменить их видимость. Во Vue нет точек и нет команды выбора отдельной точки.

Общий компонент `ProjectPanel.vue`; данные объектов приходят из

хранит только начальный выбор и подписи до ответа API.
Каждая кнопка объекта отправляет `scene.selectChapterTarget`, `{chapter, target}`.
Vue выделяет кнопку и обновляет заголовок/описание из API. Повторный выбор не отправляет
команду. Переход в раздел отправляет только `ui.selectChapter`, без автоматической
команды выбора объекта: Unreal должен брать сохранённый выбор из общего состояния.

| Группа / chapter | Кнопка → target | Начальный выбор |
| --- | --- | --- |
| Архитектура / `architecture` | Арки → `arches`; Колонны → `columns`; Пелястры → `pilasters`; Балконы → `balconies` | `pilasters` |
| Внешний пояс / `park` | Площадь → `square`; Братва → `bratva`; Лавочки → `benches`; Амфитеатр → `amphitheater`; Люстра → `chandelier`; Ресторан → `restaurant`; Парк → `park`; Деловой центр → `business-center` | `bratva` |
| Внутренний двор / `courtyard` | Тихий отдых → `quiet-rest`; Артобъект Рыбы → `fish-art`; Клумба → `flowerbed`; Уличная гостиная → `outdoor-lounge` | `fish-art` |
| МОПы / `entrance` | Гранд-Лобби → `grand-lobby`; Детская игровая → `playroom`; Спортзал → `gym` | `playroom` |

В МОПах дополнительная кнопка **«Вид»** отправляет `scene.requestInteriorView`,
`{target}` с выбранным помещением. Это запрос ракурса в Unreal; в браузере камера
не меняется, меню этажей или ракурсов не открывается. Повторное нажатие отправляет
команду снова. Обработчик и набор ракурсов в Unreal ещё не подключены.
Подписи помещений теперь приходят из `roomLabel` API; пустое значение не показывается.

Обратное состояние хранится в `chapterTargets`, например:

```js
window.IdelWidget.setState({
  view: 'courtyard',
  chapterTargets: {courtyard: 'flowerbed'}
});
```

Обновление частичное: остальные разделы сохраняют свой выбор. Несуществующие
ключи и объекты другого раздела игнорируются. `getState()` возвращает копию
словаря; её изменение не меняет UI. `setState` не отправляет команды в ответ.
При сбросе сессии восстанавливаются начальные значения из таблицы.
Это ключи UI, а не реальные ID backend или имена Actor. Связывать нужно пару
`chapter + target`, поскольку названия объектов могут повторяться между разделами.

## 8. Обратная синхронизация Unreal → Vue

Это вызовы JS API, а не события кнопок:

| Вызов | Назначение |
| --- | --- |
| `window.IdelWidget.getState()` | Возвращает `minutes`, `season`, `weather`, `hidden`, `view`, `categories`, `projectTarget`, `chapterTargets`. |
| `window.IdelWidget.setState({...})` | Частично обновляет эти поля без повторной отправки команд. `view`: `home`, `location`, `project`, `architecture`, `park`, `courtyard`, `entrance`, `apartments`, `saved`, `gallery`; неизвестные `view/projectTarget` игнорируются, неизвестные категории отбрасываются. |

| `window.IdelSession.reset()` | Сбрасывает сессию, показывает стартовый экран в полном/сессионном режиме, возвращает `view: home`, `hidden: false`, `projectTarget: section-4` все категории и начальные `chapterTargets`. Не отправляет событие выхода. |

У каждого Web Browser своё состояние. Передача между панелями не автоматическая.

браузерам в Unreal ещё предстоит реализовать. Базовая схема: [PANELS.md](PANELS.md).

## 9. Выбор квартир — экраны 11–13

Источник данных — существующий каталог API; начальное состояние: `mode: facade`,
все фильтры пустые, включая особенности, комнаты, секцию. Цены в событиях
передаются в рублях, площадь — м², ID — числовые ID backend. Макетные номера
секций из экрана «О проекте» здесь не используются.

| Источник | Команда | params / результат |
| --- | --- | --- |
| «Выбор квартир», первое открытие | `ui.apartments` | `{mode:"facade", filters}`; в полном Browser открывает фильтры. Изолированный toolbar отправляет только команду, без скрытого API-запроса; Unreal должен показать Browser-владелец квартир. |
| Открытие, изменение фильтров, сброс, повтор загрузки | `scene.apartments.query` | `{mode,filters,selectedId,detailsOpen,revision,context:{}}`; новая версия запроса. Unreal скрывает старую подсветку и готовит камеру. |
| Все страницы API загружены | `scene.apartments.results` | `{revision,items}`; актуальные квартиры. Пустой массив означает отсутствие результатов. |
| Данные получены и Unreal подтвердил готовность | `scene.apartments.highlight` | `{revision,items,selectedId}`; ровно один раз для версии. |
| «Фасад / Этажи / Списком», крестик списка | `scene.apartments.mode` | `{mode:"facade"\|"floors"\|"list"}`. Крестик списка возвращает фасад; этажи и список показывают реальные квартиры в браузере. |
| Выбор секции и этажа в режиме «Этажи» | `scene.apartments.floor` | `{revision,sectionId,floor,items}`; `items` — квартиры выбранного этажа. Отправляется после `scene.apartments.results` или при смене этажа. Unreal переводит камеру и подсветку этажа; Vue показывает вертикальный переключатель. |
| Выбор карточки списка / закрытие карточки / изменение фильтра | `scene.apartments.select` | `{id,sceneObjectKey}`; `null,null` снимает выбор. На фасаде/этажах после загрузки открывается правая карточка; в списке выбранная карточка обводится, правая скрыта. |
| «Подробнее» | `ui.apartment.details` | `{id}`; открывает модальную карточку и повторно получает актуальные данные API. |
| «Закрыть» / Escape в карточке | `ui.apartment.details.close` | `{id}`; возвращает к фасаду/списку. |
| «3D-тур» | `scene.apartment.tour` | `{id,sceneObjectKey}`; действие камеры выполняет Unreal. |
| «Вид из окна», выбор 1–3, стрелки | `scene.apartment.window` | `{id,sceneObjectKey,viewIndex}`; Vue открывает экран 14–15, стартует с вида 2 по макету. Unreal выбирает фактическую панораму/камеру для этого ID и индекса. |
| «Назад» на виде из окна | `scene.apartment.window.close` | `{id}`; Vue возвращает экран квартир, Unreal возвращает камеру. |
| Круговое управление видом | `scene.apartment.window.pan` | `{id,viewIndex,direction:'up'|'right'|'down'|'left'}`; Unreal поворачивает взгляд. Компас вызывает существующий `scene.resetNorth`. |
| Камера в режиме квартир | `scene.screenshot` | `{captureId,propertyId}`; запрос настоящего снимка сцены, `propertyId` может быть null до выбора. |
| Выход из квартир / Домой / другой раздел | `ui.apartments.close` | `{}`; Unreal убирает подсветку и отменяет переход. |

`items` содержит `{id,sceneObjectKey,rooms,status,floor,sectionId}`.
`status`: `available`, `reserved`, `sold`. `sceneObjectKey` приходит из API для квартир; если он null,
нужно явное соответствие ID квартиры и Actor в Unreal. Vue не рисует полигоны
квартир на изображении. Секция, комнаты, особенности, диапазоны и номер
используют одну команду `scene.apartments.query` с полным набором фильтров.

«С мебелью / Без мебели» переключают изображение локально; вторая кнопка
отключена, пока нет `apartment.planImageUnfurnished`. Избранное квартиры без
настоящего токена хранится локально в текущей сессии; с токеном использует
GET/POST/DELETE API по HTTPS. Команды Unreal у сердечка нет. Закрытие превью
снимка не удаляет его из истории; удаление доступно в «Сохранённом».

На экране 20 список показывает по 10 квартир на странице. Кнопки первой,
предыдущей, номерной, следующей и последней страницы меняют только локальную
страницу уже полученного каталога; отдельного события Unreal и нового GET нет.
При смене фильтров или режима страница сбрасывается на 1. «Подробнее», 3D-тур,
вид из окна и избранное карточки используют события/API выше для её ID.
Точки «Вид 1/2/3» на 3D-фоне выставляет Unreal. В браузерном превью
подложены два изображения Figma; они не считаются видом конкретной квартиры.
«Машино-места» и «Кладовые» пока неактивные подписи: запросы и события для них
не реализованы. Забронированные и проданные квартиры показаны с блокирующей
плашкой. Открытие подробной карточки в списке выполняет `scene.apartments.select`,
затем `ui.apartment.details`; приём этих команд в Unreal ещё не проверен.

### Unreal → Vue: `window.IdelApartments`

| Метод | Назначение |
| --- | --- |
| `sceneReady({revision})` | Подтвердить готовность камеры для версии из `scene.apartments.query`. Можно вызвать до загрузки API. Устаревшая версия отклоняется. |
| `select({id})` или `select({sceneObjectKey})` | Клик по квартире в 3D. Загружает карточку, без ответного события выбора; возвращает Promise<boolean>. Ключ ищется только среди загруженных результатов. `select({id:null})` снимает выбор. |
| `setScreenshot({captureId,url})` | Ответ на снимок: HTTP(S) URL, PNG/JPEG/WebP data URL, либо file URL при локальной загрузке страницы. Другой captureId или сменившаяся квартира отклоняются. |
| `beginCapture({captureId})` | Зарегистрировать запрос снимка из отдельного toolbar в Browser-владельце перед `setScreenshot`. Не отправляет повторную команду Unreal. |
| `setScreenshot({captureId,error:true})` | Сообщить ошибку снимка. Без ответа через 20 секунд показывается ошибка. |
| `setSessionToken(token)` | Установить реальный Bearer token в память этого экземпляра и загрузить избранное. `null` очищает его; токен не включается в getState и события. |
| `setFloor(number)` | Выбрать загруженный этаж текущей секции; возвращает boolean и отправляет `scene.apartments.floor`. |
| `getMaterials()` | Получить объекты избранного и снимки текущей сессии. Не содержит телефона или Bearer token. |
| `resetMaterials()` | Очистить локальные избранное, снимки и токен; вызывается при завершении сессии. |
| `setMaterials({favorites,screenshots})` | Скопировать материалы в отдельный BrowserSaved без исходящего события. Проверяет типы ID и URL. `getMaterials()` владельца служит источником. |
| `toggleFavorite({type,id})`, `removeScreenshot(id)`, `details()` | Методы Browser-владельца для обработки `ui.saved.*` из BrowserSaved; после действия синхронизировать материалы обратно. |

`IdelWidget.getState()` теперь включает `apartments: {mode,filters,selectedId,
detailsOpen,revision,windowViewIndex}`. `setState({view:'apartments',apartments:{windowViewIndex:1|2|3|null}})` возвращает
Promise и обновляет интерфейс без исходящих команд. `revision` задаётся локальным
экземпляром и не восстанавливается. Это механизм синхронизации, не запрос запуска
камеры; при программном открытии Unreal сам управляет сценой. Данные каталога,
снимок и токен в снимок состояния не входят. Вне режима квартир другие команды
работают как раньше. При сбросе сессии каталог закрывается и токен очищается.

Проверка приёма этих команд, подсветки, снимков и камер в Unreal ещё не выполнена.

У диапазонов «Этаж / Площадь / Стоимость» цифры обновляются локально во время
перетаскивания (`input`). Команда `scene.apartments.query` и запрос каталога
отправляются после завершения изменения (`change`). Обе границы используют
полную ширину общей полосы и не пересекаются.

## 10. Этажи, галерея, сохранённое и завершение сессии

| Элемент | Событие для Unreal | Локальное действие |
| --- | --- | --- |
| Секция в режиме «Этажи» | `scene.apartments.query`, затем `results` и `floor` | Обновляет фильтр и выбирает верхний доступный этаж. |
| Стрелки и номер этажа | `scene.apartments.floor` | Меняют `floorView`; счётчик берётся из загруженного каталога. |
| Миниатюра/стрелки галереи | нет | Открывает изображение из `assets/gallery`, переключает 25 макетных кадров. |
| Сердце в карточке/списке | нет | При мок-сессии меняет локальное избранное; при настоящем токене пишет через API. |
| Кнопка камеры | `scene.screenshot` | После успешного `setScreenshot` хранит снимок текущей сессии и запускает анимацию миниатюры к сердцу без числового индикатора. Один `Shot` без ответа в Vue анимацию не запускает. |
| Удалить снимок | нет | Удаляет запись из локальной истории. |
| Плашки «Снимок сохранён» / «Добавлено в избранное» | нет | Появляются после подтверждённого ответа Unreal или успешного изменения избранного, закрываются локально либо исчезают через 6 секунд. |
| «Отправить на почту» / Telegram / MAX | нет | Открывает диалог. «Отправить» отключена, пока нет серверного endpoint и провайдера; запрос не создаётся. |
| «Сохранить избранное и выйти» | `session.ended` после успешной записи | Сохраняет только избранные объекты в IndexedDB этого устройства, очищает текущую сессию. Unreal должен удалить PNG этой сессии. |
| «Выйти без сохранения» | `session.ended` | Очищает текущую сессию без записи. Unreal должен удалить PNG этой сессии. |
| Крестик BrowserSaved/BrowserGallery | `ui.panel.close {panel:'saved'|'gallery'}` | Unreal должен установить Browser Visibility=`Collapsed`; в полном Browser крестик меняет view локально. При повторном открытии Saved вызвать `IdelWidget.setState({view:'saved',hidden:false})`: Vue скрывает содержимое до стабильной разметки, нового внешнего события нет. Исправление первого кадра в Unreal ещё не проверено. |
| «Подробнее» в отдельном BrowserSaved | `ui.saved.openApartment {id}` | Unreal закрывает BrowserSaved, открывает владельца квартир, вызывает `setState({view:'apartments'})`, затем `select({id})` и `details()`. |
| Удалить избранное в отдельном BrowserSaved | `ui.saved.toggleFavorite {type,id}` | Unreal вызывает `IdelApartments.toggleFavorite({type,id})` в Browser-владельце и затем обновляет BrowserSaved через `setMaterials`. |

`IdelSession.listArchives()` возвращает метаданные сохранённых сессий,
`getArchive(id)` — избранные объекты (поле `screenshots` пустое в новых записях), `deleteArchive(id)` удаляет запись. Эти
методы возвращают Promise. Архив локален для профиля браузера, не связан с
телефоном клиента, не синхронизируется с backend и не доставляется в бота.
QR, PDF и отправка не реализованы: нужны API-04 и действующие провайдеры.
В Unreal Play подтверждена только съёмка PNG через `Shot`; возврат снимка в Vue,
анимация, BrowserSaved и удаление PNG на `session.ended` ещё не проверены.

### Секции вместо отдельного корпуса — 13.10.2026
